# API Reference

Base URL: `http://localhost:3000`. Interactive docs where you can send real requests from the browser: **`/docs`** (Scalar) or **`/swagger`** (Swagger UI). Machine-readable spec: [`openapi.json`](openapi.json) (also served at `/docs/openapi.json`).

## Conventions

- **JSON** request and response bodies, `snake_case` fields.
- **IDs** are UUID v4, generated by the server.
- **Amounts** are numbers in major currency units (₹) with at most 2 decimal places, e.g. `150.75`. They are stored as integer paise internally.
- **Timestamps** are ISO-8601 UTC with millisecond precision, generated by the server.
- **Request IDs:** every response carries an `x-request-id` header (echoed if you send one) and error bodies include `request_id`.

### Error envelope

Every non-2xx response has the same shape:

```json
{
  "error": {
    "code": "MACHINE_READABLE_CODE",
    "message": "Human readable explanation",
    "details": {}
  },
  "request_id": "0b9a6c1e-…"
}
```

For validation errors, `details` lists every problem at once:

```json
{
  "error": {
    "code": "INVALID_REQUEST_BODY",
    "message": "Request body is invalid",
    "details": [
      { "field": "type", "message": "type must be either 'credit' or 'debit'" },
      { "field": "amount", "message": "amount must be greater than 0" },
      { "field": "reference_id", "message": "reference_id is required" }
    ]
  },
  "request_id": "…"
}
```

### Error codes

| HTTP | Code                        | When                                                          |
| ---- | --------------------------- | ------------------------------------------------------------- |
| 400  | `INVALID_REQUEST_BODY`      | Missing/invalid fields, unknown fields, malformed JSON        |
| 400  | `INVALID_QUERY_PARAMETERS`  | Bad `page`, `limit` or `type`                                 |
| 400  | `INVALID_PATH_PARAMETERS`   | An id in the URL is not a valid UUID                          |
| 404  | `ACCOUNT_NOT_FOUND`         | Account id is well-formed but does not exist                  |
| 404  | `TRANSACTION_NOT_FOUND`     | Transaction does not exist on that account                    |
| 404  | `TRANSFER_NOT_FOUND`        | Transfer does not exist                                       |
| 404  | `ROUTE_NOT_FOUND`           | Unknown endpoint                                              |
| 405  | `TRANSACTION_IMMUTABLE`     | `PUT`/`PATCH`/`DELETE` on a transaction                       |
| 409  | `DUPLICATE_TRANSACTION`     | `reference_id` already used on this account                   |
| 409  | `DUPLICATE_TRANSFER`        | `reference_id` already used for a transfer from this account  |
| 415  | `UNSUPPORTED_MEDIA_TYPE`    | Body sent with an unsupported content type (e.g. XML)         |
| 422  | `INSUFFICIENT_BALANCE`      | Debit/transfer larger than the current balance                |
| 422  | `BALANCE_LIMIT_EXCEEDED`    | Credit would overflow the maximum representable balance       |
| 500  | `INTERNAL_ERROR`            | Unexpected failure (details are logged, not leaked)           |

## Accounts

### `POST /accounts`: create an account

Only `name` may be sent. `id`, `balance` (always `0`) and `created_at` are set by the server; sending them is a `400`.

```bash
curl -X POST localhost:3000/accounts -H 'content-type: application/json' -d '{"name": "Alice"}'
```

`201 Created`

```json
{
  "id": "4b8d4c4e-2f0a-4f5e-9a51-0f7a3c1d9e21",
  "name": "Alice",
  "balance": 0,
  "created_at": "2026-10-26T14:01:54.125Z"
}
```

| Field  | Rules                                         |
| ------ | --------------------------------------------- |
| `name` | required string, trimmed, 1–100 characters    |

Errors: `400 INVALID_REQUEST_BODY` (missing/blank name, or `balance`/`id`/`created_at` supplied).

### `GET /accounts/:accountId`: get an account

`200 OK` → same shape as above. Errors: `400 INVALID_PATH_PARAMETERS`, `404 ACCOUNT_NOT_FOUND`.

### `GET /accounts/:accountId/balance`: get the current balance

```bash
curl localhost:3000/accounts/$ACC/balance
```

`200 OK`

```json
{ "account_id": "4b8d4c4e-…", "balance": 100, "as_of": "2026-10-26T14:03:57.994Z" }
```

Errors: `400 INVALID_PATH_PARAMETERS`, `404 ACCOUNT_NOT_FOUND`.

## Transactions

### `POST /accounts/:accountId/transactions`: add a transaction

The balance update and the ledger entry are written atomically.

```bash
curl -X POST localhost:3000/accounts/$ACC/transactions -H 'content-type: application/json' -d '{
  "type": "credit",
  "amount": 50,
  "description": "Top up",
  "reference_id": "topup-2026-10-26-001"
}'
```

| Field          | Rules                                                                 |
| -------------- | --------------------------------------------------------------------- |
| `type`         | required, `"credit"` or `"debit"`                                     |
| `amount`       | required number, `> 0`, ≤ 1,000,000,000, at most 2 decimal places    |
| `reference_id` | required string, trimmed, 1–100 chars, unique per account             |
| `description`  | optional string ≤ 255 chars (or `null`)                               |

`201 Created`

```json
{
  "id": "df1e1067-5872-400c-a4e7-4581508d54e0",
  "account_id": "4b8d4c4e-…",
  "type": "credit",
  "amount": 50,
  "balance_after": 150,
  "description": "Top up",
  "reference_id": "topup-2026-10-26-001",
  "transfer_id": null,
  "created_at": "2026-10-26T14:01:54.172Z"
}
```

`balance_after` is the account balance immediately after this entry. `transfer_id` is set when the entry is one leg of a transfer.

**Duplicate (`409 DUPLICATE_TRANSACTION`).** Re-sending a `reference_id` already used on this account creates nothing and changes no balance. The original transaction is returned in the error details:

```json
{
  "error": {
    "code": "DUPLICATE_TRANSACTION",
    "message": "A transaction with reference_id 'topup-2026-10-26-001' already exists for this account",
    "details": { "existing_transaction": { "id": "df1e1067-…", "amount": 50, "balance_after": 150, "…": "…" } }
  },
  "request_id": "…"
}
```

**Insufficient balance (`422 INSUFFICIENT_BALANCE`).** The debit is rejected, nothing is stored and the balance is unchanged:

```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Insufficient balance to complete the debit",
    "details": { "account_id": "4b8d4c4e-…", "balance": 100, "requested_amount": 150 }
  },
  "request_id": "…"
}
```

Other errors: `400 INVALID_REQUEST_BODY`, `400 INVALID_PATH_PARAMETERS`, `404 ACCOUNT_NOT_FOUND`.

### `GET /accounts/:accountId/transactions`: transaction history

Returned **latest first** by `created_at` (ties broken by insertion order).

| Query   | Default | Rules                                            |
| ------- | ------- | ------------------------------------------------ |
| `type`  | both    | `credit` or `debit`                              |
| `page`  | `1`     | integer ≥ 1                                      |
| `limit` | `20`    | integer 1–100                                    |

```bash
curl "localhost:3000/accounts/$ACC/transactions?type=debit&page=1&limit=2"
```

`200 OK`

```json
{
  "data": [
    { "id": "…", "type": "debit", "amount": 20, "balance_after": 100, "reference_id": "d2", "created_at": "2026-10-26T14:03:57.992Z", "…": "…" },
    { "id": "…", "type": "debit", "amount": 30, "balance_after": 120, "reference_id": "d1", "created_at": "2026-10-26T14:03:57.990Z", "…": "…" }
  ],
  "pagination": {
    "page": 1,
    "limit": 2,
    "total_records": 2,
    "total_pages": 1,
    "has_next_page": false,
    "has_previous_page": false
  }
}
```

A page past the end returns `200` with `data: []` and accurate totals. Errors: `400 INVALID_QUERY_PARAMETERS`, `400 INVALID_PATH_PARAMETERS`, `404 ACCOUNT_NOT_FOUND`.

### `GET /accounts/:accountId/transactions/:transactionId`: get one transaction

`200 OK` → a transaction object. Errors: `400 INVALID_PATH_PARAMETERS`, `404 ACCOUNT_NOT_FOUND`, `404 TRANSACTION_NOT_FOUND` (including when it belongs to a different account).

### `PUT | PATCH | DELETE /accounts/:accountId/transactions/:transactionId`

Always `405 Method Not Allowed` with `Allow: GET` and code `TRANSACTION_IMMUTABLE`. To correct a mistake, post a compensating transaction. The database also refuses updates and deletes via triggers.

## Transfers (bonus)

### `POST /transfers`: move money between accounts

Creates a transfer record plus a **debit** on the source and a **credit** on the destination, all in one database transaction. Any failure rolls back all three.

```bash
curl -X POST localhost:3000/transfers -H 'content-type: application/json' -d '{
  "from_account_id": "'$A'",
  "to_account_id": "'$B'",
  "amount": 30,
  "reference_id": "rent-oct",
  "description": "Rent split"
}'
```

| Field             | Rules                                                                    |
| ----------------- | ------------------------------------------------------------------------ |
| `from_account_id` | required UUID of an existing account                                     |
| `to_account_id`   | required UUID of an existing account, different from the source          |
| `amount`          | same rules as transactions                                               |
| `reference_id`    | required, unique per **source** account (shared with its transactions)   |
| `description`     | optional, copied onto both legs                                          |

`201 Created` (A had 100, B had 50):

```json
{
  "id": "9c3e…",
  "from_account_id": "A…",
  "to_account_id": "B…",
  "amount": 30,
  "description": "Rent split",
  "reference_id": "rent-oct",
  "created_at": "2026-10-26T14:03:58.001Z",
  "debit_transaction":  { "account_id": "A…", "type": "debit",  "amount": 30, "balance_after": 70, "reference_id": "rent-oct",         "transfer_id": "9c3e…", "…": "…" },
  "credit_transaction": { "account_id": "B…", "type": "credit", "amount": 30, "balance_after": 80, "reference_id": "transfer:9c3e…",  "transfer_id": "9c3e…", "…": "…" }
}
```

Errors: `400 INVALID_REQUEST_BODY` (including same source and destination), `404 ACCOUNT_NOT_FOUND` (details name the missing id), `409 DUPLICATE_TRANSFER`, `409 DUPLICATE_TRANSACTION` (the `reference_id` was already used by a regular transaction on the source), `422 INSUFFICIENT_BALANCE`.

### `GET /transfers/:transferId`: get a transfer

`200 OK` → same shape as above. Errors: `400 INVALID_PATH_PARAMETERS`, `404 TRANSFER_NOT_FOUND`.
